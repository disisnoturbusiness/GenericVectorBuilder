## Summary

The 8 area audits produced about 125 findings; merging duplicates (Qdrant deadline x3, stall watchdog x4, "Completed with nothing read" x3, secrets x3, health x2, disk space x5) left the 75 rows above, and ranks 1-15 were all VERIFIED in the current source, none NOT FOUND, though several cited lines had drifted (GvbServices :37 to :54, ScanEndpoints :38 to :79, Program :25-26 to :36). Checking the code also corrected four area claims: the web app wires every engine sink as an optional destination (Web/Program.cs:27-28), so the engine timeout and cancel gaps (#6, #22-#26) hit the production run worker, not just Bench; the web already probes optional engines before a run (Web/Endpoints/RunEndpoints.cs:94 calls `DestinationCatalog.UnreachableAsync`), so "no sink health check" was dropped; duplicate sink names are already rejected (Core/Configuration/GvbServices.cs:277-279), so that item was dropped; and git clones do check free disk (Web/Git/GitWorkspace.cs:307), and code files are capped at 1 MB. Also dropped for having no file:line: compose-wide `logging:` and `cpus:` limits, `up -d` without `--wait`, and SqliteStateStore blocking I/O. The dominant theme is that nothing catches a hang: one run worker, no progress watchdog (#1), no Qdrant deadline (#2), engines with infinite or hour-long timeouts (#22-#25), and systemd's watchdog off with a health endpoint that always says 200 (#7, #13); those four fixes together are the first batch. The second theme is status that lies: runs ending Completed with tables rejected or zero rows read (#3), Cancel reported as Failed (#9), and the cause of a Partial run silently dropped past 20 notes (#11). Nothing was built or run for this compile; "probe" claims rest on the area auditors' scratch tests.
